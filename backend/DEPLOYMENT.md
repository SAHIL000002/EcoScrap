# EcoScrap API — deployment runbook

The Android release APK must not talk to `localhost`. This file is the exact
path from "no public API" to "APK points at a real backend".

## 0. Prerequisite: the code has to be in a git repository

Render and Railway both deploy **from a Git provider**. This workspace is not a
git repo yet, so push it first (any private repo works):

```powershell
cd "C:\Users\asahi\OneDrive\Desktop\Kabadi wala"
git init
git add .
# create .gitignore first — never commit backend/.env (it holds Atlas + JWT secrets)
git commit -m "EcoScrap: mobile app (screens 1-11) + API"
# then push to your GitHub repo
```

`backend/.env` must stay out of git; only `.env.example` is committed.

## 1. Render (recommended — free tier, stable URL)

1. Render dashboard → **New +** → **Blueprint** → select the repository.
2. Render reads `render.yaml` and prompts for the values marked `sync: false`:
   - `MONGO_URI` — the existing Atlas URI (same value as `backend/.env`), so the
     deployed API serves the already-seeded data.
   - `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` —
     optional. Without them, photo uploads fall back to local disk (see warning below).
   - `CLIENT_URL` — any value; the API does not use it for auth.
   - `JWT_SECRET` is generated by Render, nothing to paste.
3. Wait for the deploy to finish and open the health endpoint:

```
https://ecoscrap-api.onrender.com/api/v1/health
```

Expected body:

```json
{ "success": true, "message": "EcoScrap API is running", "database": "connected", "timestamp": "..." }
```

4. The public API base URL is then:

```
https://ecoscrap-api.onrender.com/api/v1
```

## 2. Railway (alternative)

1. Railway → **New Project** → *Deploy from GitHub repo* (same repository).
2. Railway reads `railway.json` + `Procfile`.
3. Add the variables manually in the service's **Variables** tab:
   `MONGO_URI`, `JWT_SECRET`, `JWT_EXPIRES_IN=7d`, `NODE_ENV=production`
   (+ the optional `CLOUDINARY_*`).
4. Public base URL: `https://<service>.up.railway.app/api/v1`

## 3. Hand the URL to the mobile release build

The app reads its API base URL from a single line
(`mobile-app/src/constants/theme.js`):

```js
export const API_BASE_URL = process.env.EXPO_PUBLIC_API_URL || 'http://localhost:5000/api/v1';
```

`EXPO_PUBLIC_*` variables are inlined by the bundler at **build** time, so the
URL is supplied per build — put it in the EAS profile that builds the APK:

```jsonc
// mobile-app/eas.json  ->  build.preview.env
"env": {
  "EXPO_PUBLIC_API_URL": "https://ecoscrap-api.onrender.com/api/v1"
}
```

Then rebuild the APK. Nothing in the app source needs to change, and the
`localhost` fallback keeps working for `expo start` during development.

## Known deployment limitations (pre-existing, not regressions)

- **Uploads are ephemeral without Cloudinary.** `ImageService` falls back to
  `/uploads/<file>` on the server's disk, which is wiped on every redeploy on the
  Render free tier. Set the three `CLOUDINARY_*` variables for durable photos.
- **Free tier cold start.** The free instance sleeps after inactivity, so the
  first request after a pause can take ~30 s. The app already treats a failed
  request as an offline/cache state, but a first login may feel slow.
- **Rate limit.** 300 requests / 15 min per device IP (`app.js`); `trust proxy`
  is set so the real device IP is used behind the platform proxy.
